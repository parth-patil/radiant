Radiant as an infinite whiteboard: ways to bring in Excalidraw

Mockups and ideas for adding free sketching, shapes, sticky notes, arrows and frames to Radiant’s canvas, either by embedding Excalidraw or by building the same things natively. Everything here is a proposal for you to choose from. No app code was changed.

Already endlessPan has no limits and zoom runs from 0.01% to 800% today. The missing piece is objects that are not nodes.
48 ideasEach with its own mockup, a reason to care and a rough size. 7 are flagged speculative.
5 routesEmbed as a layer, embed per node, build natively, interop only, and a hybrid.
MITExcalidraw’s licence, and the licence of the two small libraries its look depends on.
Recommendation in short

Do not embed Excalidraw in the main canvas. Build free canvas elements natively, in slices, and adopt Excalidraw’s file format rather than its code. Start with a first slice that needs no new document model at all: make the existing islands, floating nodes and camera feel like a whiteboard, and add .excalidraw import, export and paste. Then add a real element model that draws through Radiant’s own WebGL renderer using two small MIT libraries (rough.js for the sketchy strokes, perfect-freehand or the existing ink code for the pen). The reasons are in the recommendation.

1 · Starting point

Where Radiant is today, and what Excalidraw brings

Radiant is closer to an infinite canvas than it looks. The camera and the document already allow it; what is missing is any object that is not a mind-map node. The file and line references below are from the current source.

Radiant today

  • The camera is already unbounded. panBy has no limits, and zoom is clamped to 0.0001–8. The mesh shader splits its offset into high and low parts so far-away content stays precise. src/lib/render/camera.ts:3-4, 104-109; render/renderer.ts:682-685
  • A document can hold many roots. Doc.roots is documented as “main and floating nodes, in z-order”, each with a world position and its own layout. Layout loops over every root. Double-clicking empty canvas already creates a floating node there, and Detach turns any branch into one. core/types.ts:192-198, 263-265; core/layout/layout.ts:166; ui/controller.svelte.ts:2312-2318; core/model/commands.ts:304-318
  • Ink exists, but only per node. A node can carry a sketch: strokes with per-point pressure, stored as 0–1 coordinates inside a fixed 156 × 108 frame placed on or beside the node, up to 96 strokes of 512 points. The pad handles coalesced pointer events and a stylus eraser button. Strokes become triangles in the WebGL overlay mesh and the same polygons in SVG export. core/geometry/ink.ts:4-13, 53-96; ui/InkOverlay.svelte:25-47, 61-73; ui/pipeline.ts:599-610
  • The Hand-drawn theme bends outlines. outlineWobble derives a seeded bend per node; the rectangle shader warps its distance field with the same coefficients, and export samples the same outline, so canvas and file agree. The organic branch style adds seeded curvature. There are no rough double strokes and no hachure fills. core/geometry/hand-drawn.ts:4-50; render/shaders.ts:85-87; ui/export-visual.ts:55
  • Cross-links join two nodes, in a DOM layer. A CrossLink has from and to node ids, a bend, dash, arrowheads and a label. Its geometry is one quadratic curve clipped to both boxes, drawn as SVG above the canvas and moved by the camera. An end cannot be a point or a shape. core/types.ts:200-212; core/geometry/link.ts:9-16; ui/Connections.svelte:32-49
  • Pictures attach to nodes. A node stores a content hash, aspect and scale for a local picture, and optional generated picture or SVG art for a subtree. Bytes are kept once per SHA-256 in the SQLite assets table. Dropping a file on the canvas attaches a picture to a node. core/types.ts:129-141, 166-172; docs/file-format.md; ui/controller.svelte.ts:2628-2640
  • Export is built from the scene. One SVG is assembled from rectangles, branches, pictures, labels, ink and links. PNG is that SVG rasterised; PDF goes through jsPDF and svg2pdf, a page per tile. Anything new has to emit SVG from the same geometry to keep the “export matches canvas” rule. ui/export-visual.ts:377-467
  • Every edit is an op with an inverse. Eleven op kinds (insert, remove, move, set, setRoot, link, unlink, linkStyle, setLink, aiJob, docMeta) grouped into labelled transactions with a source of user or an AI job. Ops are logged in SQLite with their inverses. core/types.ts:283-306; docs/file-format.md
  • Useful pieces already present: a mini-map, Zoom to Fit, marquee selection through a spatial index, a dot grid, branch boundaries, presentation mode with stops, JSON Canvas export, and “type to edit” on a focused node. ui/Minimap.svelte; ui/keymap.ts:53; ui/controller.svelte.ts:2102-2143, 1047-1061, 2444-2449; render/renderer.ts:579-588; core/io/canvas.ts:21-22

What Excalidraw brings

  • Licence: MIT, copyright 2020 Excalidraw. LICENSE
  • It is a React component. @excalidraw/excalidraw 0.18.1 needs react and react-dom (17, 18 or 19) as peer dependencies, its CSS file imported, a parent with a height, and client-side rendering only. It downloads its fonts from a CDN unless you self-host them and set window.EXCALIDRAW_ASSET_PATH. package README, npm registry
  • Size. Bundlephobia reports 1.12 MB minified (353 KB gzip) for the main chunk of 0.18.1, plus lazy chunks, the largest 1.82 MB (735 KB gzip). The published dist/prod folder is 17.7 MB, of which 13.1 MB is fonts and 1.6 MB is locale files. bundlephobia, jsDelivr file listing
  • Rendering is Canvas 2D. Shapes are generated with rough.js and freehand outlines with perfect-freehand; both are ordinary dependencies. renderElement.ts, shape.ts
  • An open file format. .excalidraw is plain JSON: type: "excalidraw", version: 2, elements, appState, files. The clipboard uses the same shape with type: "excalidraw/clipboard". Libraries are .excalidrawlib files with libraryItems. JSON schema docs, constants.ts
  • Element types: rectangle, diamond, ellipse, text, line, arrow, freedraw, image, frame, embeddable, iframe and magic frame, plus a sticky note on the master branch. Every element has position, size, angle, stroke and fill colours, fillStyle (hachure, cross-hatch, solid, zigzag), roughness, a seed, groupIds, frameId, locked, link and free-form customData. element types.ts
  • Arrow binding. An arrow end stores the element it is bound to, a fixed point on that element as two 0–1 ratios, and a mode. Arrows can be elbowed and carry a text label. Frames clip their children; arrows are never clipped. frames docs
  • An imperative API (updateScene, getSceneElements, scrollToContent, setActiveTool, onChange, onScrollChange) and export helpers (exportToSvg, exportToBlob, exportToCanvas, exportToClipboard). API docs, export docs
  • Mermaid conversion as a separate MIT package that returns editable element skeletons for flowchart, sequence, class, ER, state, Gantt, quadrant and timeline diagrams. mermaid-to-excalidraw
  • Collaboration is not in the package. Live rooms, end-to-end encryption and shareable links belong to the hosted app in the same repository, which uses socket.io and Firebase. repository README
  • Paid Excalidraw+ adds cloud storage with unlimited scenes, access control, read-only links and embeds, presentations from frames, PDF and PPTX export of frames, comments, voice and screen sharing, and a larger AI allowance. The free hosted editor keeps every drawing tool, libraries, PNG and SVG export and ten AI requests a day. pricing page

Alternatives that solve the same problem

tldraw

A capable React canvas SDK, but its licence does not allow production use without a licence key from the vendor; development use is allowed, and a watermark is enforced. Not a drop-in for a shipped app. LICENSE.md, licence key docs

rough.js on its own

MIT, about 27 KB minified (9 KB gzip). Its generator returns drawing operations for lines, rectangles, ellipses, polygons, curves and paths without touching a canvas, and can turn them into SVG path data. That is exactly what a WebGL renderer plus SVG export needs. repository, generator.ts

perfect-freehand on its own

MIT, about 4 KB minified (2 KB gzip), no dependencies. getStroke turns input points with pressure into the outline polygon of a stroke. Radiant’s own inkPolygons already does a simpler version of this. repository

JSON Canvas

Obsidian’s open, MIT-licensed format for infinite canvases: text, file, link and group nodes plus edges. Radiant already exports it. It has no shapes, ink or styling, so it complements the Excalidraw format rather than replacing it. spec; core/io/canvas.ts:21-22

2 · How to do it

Integration routes, side by side

Five ways to get there. A1 and A2 use Excalidraw’s code as it is. B re-implements the drawing tools inside Radiant’s renderer. C only exchanges files. D is the mix I recommend.

  • core/ pure TypeScript
  • render/ WebGL
  • ui/ Svelte
  • host/ and SQLite
  • Excalidraw, React or its file formats

A1 · Embed Excalidraw as a canvas layer Large to make seamless · estimate

Mount a React root inside the Svelte app and stack the <Excalidraw /> component, with a transparent background and its own toolbar trimmed, over the WebGL canvas. Three bridges keep the two in step.

You get
Every Excalidraw tool on day one: shapes, arrows with binding, pen, text, frames, libraries, the Mermaid dialog, its polish and its future updates.
It costs
React and react-dom in the app; about 1.1 MB of minified script before lazy chunks; fonts that must be self-hosted for offline use; a bridge to maintain against a package that is still pre-1.0.
Risks
The four numbered seams below. They sit exactly on Radiant’s stated quality bars.
  • 1 Camera. Feasible through scrollX, scrollY, zoom and onScrollChange, but Excalidraw clamps zoom to 10%–3000% and Radiant to 0.01%–800%. Below 10% the layers cannot stay aligned, so sketches would have to hide or the map’s zoom be limited.
  • 2 Undo. Two histories. Each Excalidraw change needs a marker in Radiant’s stack, and undo has to be routed to whichever side owns the step, including after reload.
  • 3 Two renderers and two input layers. Canvas 2D repaints over WebGL on every camera move. Whichever canvas is on top takes the pointer, so there is a mode switch, no marquee across both, and sketches are either all above or all below the map. Arrows cannot bind to nodes unless every node is mirrored as an invisible locked rectangle.
  • 4 Document and export. The drawing is an opaque blob beside the map, outside the op log except as whole-blob replacements. Export means merging exportToSvg output into Radiant’s SVG, with its own fonts, and hoping svg2pdf agrees.

A2 · Embed Excalidraw per node, as a “sketch” attachment Small to medium · estimate

A node gets a Sketch attachment. Opening it shows a full Excalidraw editor in a sheet, loaded only then. On close, the scene JSON and an SVG preview are stored as assets, and the preview is drawn through the existing picture pipeline.

You get
A real Excalidraw editor for diagrams that belong to a node, with exact export because the preview is the drawing. One undo step per editing session.
It costs
The same React and package bytes, but only when a sketch is opened. Two new optional fields on a node.
Risks
It is a different feature. It gives you drawings attached to nodes, like the Obsidian plugin does for notes, and none of the infinite-canvas feel you asked for. It also overlaps with the existing ink sketch.

Honest use: a time-boxed spike if you want Excalidraw-quality diagrams on nodes this month, kept behind a lazy import so it can be removed.

B · Re-implement the drawing tools natively Large in total, in medium slices · estimate

Add canvas elements to the document as first-class objects with their own ops. Geometry lives in core/: rough.js’s generator produces the sketchy strokes and hachure lines, a freehand routine produces pen outlines, and both are tessellated into the same Mesh type the branch renderer already draws. The same strokes are written as SVG paths for export.

You get
One camera, one selection, one undo history, one file. Arrows that bind to nodes. Free z-order relative to maps. Export that matches by construction, the way ink and outline wobble already do.
It costs
Two small MIT libraries (about 27 KB and 4 KB minified). A change to the coordinator-owned core/types.ts, new ops, a file-format bump from v3 to v4 with a migration, and one extra mesh draw call per frame.
Risks
Scope. Excalidraw’s years of polish are in the editing: resize and rotate handles, arrow routing, text inside shapes, snapping. Each needs building. Text over filled shapes must still pass the 4.5:1 label contrast gate.

Budget notes: the branch mesh is untouched, so the “one branch draw call” rule holds; a static element mesh costs nothing while idle and only a uniform change while panning; element spans can be culled exactly like branch spans (render/renderer.ts:655-674).

C · Interop only Small to medium · estimate

No drawing tools. A pure TypeScript converter reads and writes .excalidraw files, the clipboard payload and .excalidrawlib libraries, mapping what it can onto today’s document and reporting what it dropped.

You get
Round trips with excalidraw.com and every tool that speaks the format. A map exported as boxes and arrows you can keep sketching on elsewhere.
It costs
No new dependencies and no model change. It sits beside the existing importers in core/io.
Risks
Lossy both ways: freehand, frames, groups and unbound arrows have no home in today’s document, and tapered branches have no Excalidraw equivalent. Nothing can be drawn in Radiant.

D · Hybrid: native elements, Excalidraw’s formats Recommended

Route B, built in slices, with route C’s converter as its file layer, preceded by a first slice that needs no new model. Borrow Excalidraw’s element schema, file and clipboard formats, stencil format and tool conventions. Do not borrow its renderer or its React UI.

You get
The infinite-canvas feel quickly, then real free objects that obey Radiant’s rules, and compatibility with the Excalidraw ecosystem throughout.
It costs
What B costs, spread over phases, each of which is useful on its own.
Risks
Discipline: resisting the embed shortcut when a tool turns out to be fiddly. A2 stays available as a spike if you want one.

Recommendation and why

Take route D.

  1. What you like is mostly already here. The canvas pans without limit, zooms across nearly five orders of magnitude and holds any number of roots. The feeling is missing because nothing but nodes can live on it. That is a document-model question. Embedding Excalidraw does not give Radiant a model; it gives it a second application sharing the window.
  2. The embed’s seams land on your own quality bars. Export must match the canvas, the frame budget is 8.3 ms with at most 4 ms of script, nothing draws when idle, and there is one undo history. A1 strains all four, and the zoom-range mismatch is a hard limit, not a tuning problem.
  3. Radiant already owns the three hard primitives. A seeded wobble that matches between shader and export, pressure ink tessellated into a mesh, and SVG export built from scene geometry. Sketchy shapes are those same patterns with more geometry. rough.js’s generator and perfect-freehand are small, MIT and pure maths, so they fit the rule that core/ has no DOM.
  4. The format is the valuable part of Excalidraw to adopt. Using its element fields for free objects makes import, export, paste, stencil libraries and Mermaid conversion nearly free, and keeps an embed spike possible later without a data migration.
  5. It can start this week. Phase 0 is UI work on features that exist. If the whiteboard feel is not what you hoped once islands, notes and navigation are in place, you will have found out before paying for an element model.
3 · What it could be

Ideas gallery

48 ideas in seven groups. Each has a small mockup, what it is, why you might care, what it builds on in the current code, and a rough size. Sizes are estimates: small is days, medium is one to three weeks, large is more, for one person who knows the codebase. Speculative ideas are flagged; they depend on something untested.

A. The canvas itself

Radiant can already pan without limit and hold several roots. These ideas make that obvious and easy to move around in. Most need no change to the document model.

01Small · estimate

Islands: several maps on one endless canvas

Treat every root as an island you can drop anywhere. Double-click empty space to start one, drag a whole island by its root, and show its title large when zoomed far out.

Why you would care: This is the infinite-canvas feel, and the model already supports it: only the affordances are missing.

Builds on: Doc.roots and RootInfo.position (core/types.ts:192-198, 263-265); double-click already calls createFloating (ui/controller.svelte.ts:2312-2318).

02Small · estimate

Zoom to fit everything, with readable overview

One key frames every island, note and frame. Below a zoom threshold, swap unreadable labels for island titles and frame names drawn at a fixed screen size.

Why you would care: An endless canvas is only pleasant if you can always get back to the whole picture and still read it.

Builds on: Camera.fitState (render/camera.ts:112-128); overviewTitle on labels (core/types.ts:448-451); Zoom to Fit command (ui/keymap.ts:53).

03Small · estimate

A mini-map that shows everything

Extend the existing mini-map to draw notes, shapes and frames as well as nodes, with one colour per kind, and let a click or drag move the camera there.

Why you would care: On a large canvas the mini-map becomes the main way to get around.

Builds on: ui/Minimap.svelte draws node boxes only (lines 10-21) and already drags the viewport.

04Small · estimate

Bookmarks: named views of the canvas

Save the current camera as a named view. A short list and number keys jump between views with the existing animated camera.

Why you would care: Lets you keep a sketch corner, an overview and a detail area one keystroke apart.

Builds on: CameraState is three numbers (core/types.ts:523-528); Camera.animateTo exists. Storing views in the document needs a docMeta key from the coordinator.

05Medium · estimate

Portals between distant regions

A small link object that flies the camera to another island, frame or bookmark, with a Back control that returns you to where you were.

Why you would care: Makes a huge canvas feel connected instead of scattered.

Builds on: node.link and the Back button for linked maps (ui/TopBar.svelte:38-41, mapLinkTrail).

06Small · estimate

Edge compass for off-screen things

When islands, frames or search hits lie outside the window, show small pointers on the nearest edge. Click one to fly there.

Why you would care: You stop losing things. Cheap to build because it only needs bounds and the camera rectangle.

Builds on: Camera.visibleRect (render/camera.ts:84-89) and layout bounds per root.

07Medium · estimate

Grid, snapping and alignment guides

Show guides when an edge or centre lines up with a neighbour, mark equal gaps, and optionally snap to the dot grid that the Grid theme already draws.

Why you would care: Free objects look tidy without effort, which is most of why whiteboards feel good.

Builds on: Dot grid shader with a 32-unit pitch (render/renderer.ts:579-588); spatial index queries (core/geometry/spatial.ts).

08Small · estimate

Find flies the camera

Let Find search notes, free text and frame names as well as nodes, and animate from hit to hit across the canvas.

Why you would care: On an endless canvas, search is also navigation.

Builds on: ui/Finder.svelte searches nodes today (Mod+F, ui/keymap.ts:23).

09Small · estimate

Camera history: back and forward

Remember the last few places the camera rested. Two key chords step back and forward through them, like a browser.

Why you would care: After jumping to check something far away, one key returns you to your place.

Builds on: Camera.subscribe (render/camera.ts:42-45) gives every camera change; this is UI state only.

B. Free objects beside the tree

Things that do not have to belong to any map: notes, shapes, text, arrows, ink, pictures. The first two can ship on the existing model; the rest need a canvas-element model (route B).

10Small · estimate

Sticky notes that live outside any tree

A note tool that drops a coloured note anywhere. The first version can be an ordinary floating root with a box shape and fill colour, so it saves, undoes and exports today.

Why you would care: The fastest way to get whiteboard behaviour: capture first, organise later.

Builds on: Floating roots plus NodeStyle.shape and fillColor (core/types.ts:54-71). Excalidraw master also has a stickynote element type.

11Medium · estimate

Free shapes with sketchy fills

Rectangle, ellipse and diamond with hachure, cross-hatch or solid fill, a roughness setting, and text inside. Geometry comes from a seeded generator so a shape looks the same every time.

Why you would care: This is the Excalidraw look, and it suits rough thinking better than tidy boxes.

Builds on: Excalidraw element fields fillStyle, roughness, seed (packages/element/src/types.ts); Radiant already seeds wobble per node (core/geometry/hand-drawn.ts:8-13).

12Small · estimate

Text anywhere

Press T and click to type on bare canvas, in the hand-drawn face or the map font. No box, no branch.

Why you would care: Titles, labels and asides are the glue of a whiteboard.

Builds on: A free label is one LabelDraw in the existing text atlas (core/types.ts:440-468); as with notes, a first version can be a floating root with shape none.

13Medium · estimate

Arrows that bind to nodes and to shapes

Draw an arrow from anything to anything. Ends snap to a node, a note or a shape and stay attached when either side moves, with an optional label.

Why you would care: Lets a sketch point at the exact branch it is about, which neither tool can do alone.

Builds on: CrossLink joins two node ids only (core/types.ts:207-212, core/geometry/link.ts:9-16). Excalidraw stores startBinding and endBinding with a fixed point on the target.

14Medium · estimate

Freehand pen with pressure, anywhere

A pen that draws on the canvas itself, not only in a fixed pad on a node. Width follows stylus pressure and the stroke is stored as points so it stays sharp at any zoom.

Why you would care: Circling, underlining and scribbling over a map is the quickest kind of thinking.

Builds on: InkStroke with per-point pressure, inkPolygons and inkMesh (core/geometry/ink.ts:4-8, 53-96); today strokes live inside a 156 x 108 frame per node (ink.ts:12-13).

15Medium · estimate

Drop pictures, PDFs and links on the canvas

Drag a file or URL onto empty canvas and it becomes a free card: a picture, a PDF page preview or a link card. Dropping onto a node still attaches it to that node.

Why you would care: Reference material sits next to the thinking it supports.

Builds on: onDrop accepts pictures and attaches them to a node (ui/controller.svelte.ts:2628-2640); bytes are stored once by SHA-256 in the assets table (docs/file-format.md).

16Large · estimateSpeculative

Web embeds and live cards

A card that shows a live web page, video or sheet inside the canvas. It would be a DOM element floating over the WebGL canvas and tracking the camera.

Why you would care: Useful for research boards, but it is the least local-first idea here.

Builds on: Excalidraw has embeddable and iframe elements with a validateEmbeddable hook. In Tauri this needs a content-security decision and an allow-list. Speculative.

17Medium · estimate

Stencil libraries

A side panel of reusable drawings. Import the open .excalidrawlib format, save any selection as a stencil, and drag stencils onto the canvas.

Why you would care: Hundreds of free community stencils exist in that format, so the library is full on day one.

Builds on: ExportedLibraryData: type excalidrawlib, version 2, libraryItems (packages/excalidraw/data/types.ts). Needs the element model from route B.

18Medium · estimate

Groups, locking and stacking order

Group free objects so they move together, lock anything so it cannot be nudged, and send objects forward or back. A locked map makes a safe background to draw over.

Why you would care: Stops accidental drags, which is the main annoyance on a busy board.

Builds on: Excalidraw elements carry groupIds, locked and a fractional index for order. Doc.roots is already documented as z-order (core/types.ts:263).

19Medium · estimate

Flowchart mode: grow the next box with a key

With a shape selected, a modifier plus an arrow key adds a connected shape in that direction. Elbow connectors route around boxes.

Why you would care: Turns the canvas into a quick process-mapping tool without leaving the keyboard, like Tab does for a map.

Builds on: Excalidraw help lists Cmd/Ctrl+Arrow to create a flowchart and Alt+Arrow to navigate it; arrows have an elbowed flag with fixed segments.

C. Frames and presenting

A frame is a named rectangle that owns what is inside it. It is also a natural presentation stop, which ties this work to the presentation feature being designed separately.

20Medium · estimate

Frames that group a region

Draw a named frame around any mix of maps, notes and sketches. Moving the frame moves its contents, and its name stays readable when zoomed out.

Why you would care: Gives the endless canvas rooms, so a big board has structure.

Builds on: Excalidraw frame element: children carry frameId, are ordered before the frame and are clipped to it (docs.excalidraw.com/docs/codebase/frames).

21Medium · estimate

Frames as presentation stops

Present walks the frames in order, fitting each to the screen, instead of only walking branches. A stop could also be a node or a bookmark.

Why you would care: One canvas becomes the deck. This is how Excalidraw+ presentations work, and it fits the presentation feature you are designing.

Builds on: Presentation stops are a list of node ids today (ui/controller.svelte.ts:226, 1047-1061) with Previous / Next controls (ui/CanvasViewBar.svelte:14-23).

22Small · estimate

Laser pointer and fading ink

A pointer that leaves a short glowing trail, and a highlighter whose strokes fade after a few seconds. Neither is saved to the document.

Why you would care: For walking someone through a map on a call without marking it up.

Builds on: Excalidraw has a laser tool (key K) and a separate @excalidraw/laser-pointer package. In Radiant this is overlay geometry only, with no ops.

23Medium · estimate

Review layer: annotate over a locked map

A separate layer for comments, circles and notes drawn over a map that cannot be edited underneath. Show, hide or clear the layer in one step.

Why you would care: Mark up a map for someone, or review an AI-generated one, without touching the original.

Builds on: Needs element layers plus lock. Fits the AI provenance work already present (ui/AiProvenancePanel.svelte, AiChangeSummary.svelte).

24Small · estimate

Export: one page per frame

Export every frame as its own PNG or SVG, or as one multi-page PDF in frame order.

Why you would care: Frames then double as hand-outs and slides with no extra layout work.

Builds on: pdfBytes already loops over pages (ui/export-visual.ts:418-424) and export accepts a viewport crop (line 452).

25Small · estimate

Storyboard strip

A strip of frame thumbnails along the bottom. Drag to reorder the talk, click to fly to a frame, hide a frame from the run.

Why you would care: You can see and fix the order of a presentation without hunting across the canvas.

D. Between sketch and structure

The ideas neither tool has on its own: moving material between loose whiteboard objects and a structured map, in both directions.

26Medium · estimate

Lasso loose notes, then “Make this a map”

Select a pile of notes and turn them into a mind map in one step: the note you pick, or the largest, becomes the root and the rest become its children, placed by the normal layout.

Why you would care: Brainstorm messily, then get structure for free. Miro has no built-in way to do this, so it would be a real difference.

Builds on: With notes as floating roots, this is one transaction of move ops that re-parent roots (core/types.ts:290).

27Large · estimateSpeculative

Sketch to branch

Draw boxes and lines by hand, then ask Radiant to read the drawing: recognise the words and the connections and rebuild it as a real branch you can edit.

Why you would care: Paper-style capture with a stylus, structured afterwards. Speculative: recognition quality would decide whether it is useful.

Builds on: Would send a rendered crop to the existing AI provider and apply the result through the stream applier (core/ai/stream.ts). Not tested.

28Medium · estimate

Branch to loose notes

The reverse: detach a branch into free notes joined by arrows, so you can rearrange freely, then put it back together.

Why you would care: A tree can be too rigid in the middle of a rethink. This lets you loosen it without retyping anything.

Builds on: detach already turns a node into a floating root (core/model/commands.ts:304-318); the arrows would be ordinary cross-links.

29Medium · estimate

The whole map in the Excalidraw look

A theme that draws branches, outlines and fills with the same rough, doubled strokes and hachure as free shapes, in a hand-drawn face, with a roughness setting.

Why you would care: Maps and sketches then look like one drawing, and rough maps invite editing.

Builds on: Theme.handDrawn warps outlines today (core/geometry/hand-drawn.ts, render/shaders.ts:85-87) and the organic branch style adds seeded curvature; neither has rough double strokes or hachure.

30Large · estimate

A node that opens into its own canvas

Any node can hold a private canvas. Zooming into it, or pressing a key, takes you inside; a breadcrumb takes you back out. The node shows a small preview.

Why you would care: Depth without clutter: a detailed flow lives inside the node it explains.

Builds on: Could reuse linked maps (core/io/map-links.ts, copy-map-link command) or store a nested element set on the node. The second needs the element model.

31Small · estimate

Drag a note onto a node to adopt it

Drop a free note on a node and it becomes that node’s child, text and colour kept. Drag a child out past a threshold and it becomes a free note again.

Why you would care: The smallest possible bridge between the two worlds, and it matches how FigJam and Heptabase behave.

Builds on: Drag re-parenting and the detach key during a drag already exist (ui/controller.svelte.ts:2346, core/model/commands.ts:304).

32Medium · estimate

Any shape can grow a branch

Select a shape or note and press Tab: it becomes the root of a new branch, keeping its sketchy outline. Radiant’s layout takes over from there.

Why you would care: Start with a doodle, end with a map, without choosing a tool up front.

Builds on: A shape that owns children is a root with a custom outline; needs a link between an element and a root, or a new NodeShape (core/types.ts:20-26, coordinator-owned).

33Small · estimate

A bigger sketch pad on each node

Let the existing per-node ink pad be resized and hold more strokes, so a node can carry a proper diagram rather than a thumbnail doodle.

Why you would care: A near-term win that needs no new model, and it keeps drawings attached to the idea they belong to.

Builds on: INK_WIDTH 156, INK_HEIGHT 108, 96 strokes of 512 points (core/geometry/ink.ts:10-13); ui/InkOverlay.svelte draws the pad.

Tidy up a messy selection

One command arranges selected notes into a grid, row or column, or clusters them by colour, with even gaps.

An agent or command line that draws

Give the agent interface element operations as well as node operations, so a coding agent can add a diagram, annotate a map or lay out a board, each as one undo step.

Why you would care: You keep using Excalidraw where it is better and nothing is trapped on either side.

Selection across both kinds of object

  • Click selects one object, whichever is on top: a node, a note, a shape, an arrow or a frame’s edge.
  • Drag from empty canvas draws a marquee, as now. It collects nodes through the spatial index and elements through the same index. ⌥-drag draws a free lasso.
  • A node moves with its subtree, as now. A free element moves alone, or with its group or frame.
  • ⌘-click reaches inside a group or frame, the way Excalidraw’s deep select does.
  • Arrow keys keep navigating the tree when a node is focused. With only elements selected they nudge.
  • Delete on a mixed selection is one transaction and one undo step. Deleting a node keeps today’s rule of removing its subtree.
  • Locked objects and the contents of a locked map are skipped by the marquee, so drawing over a map cannot disturb it.
5 · In what order

A phased plan

Sizes are rough estimates of relative effort, not schedules. Each phase leaves the app shippable. The idea numbers refer to the gallery.

Phase 0 · Make the canvas feel endless Small · estimate

UI only, no change to the document. Islands as a headline feature, fit-all with readable overview titles, the mini-map showing everything, edge pointers, camera history, the slash menu, the Hand tool and ⇧1.

Ideas 1, 2, 3, 4, 6, 8, 9, 48. Touches ui/; bookmarks need one docMeta key.

Phase 1 · Notes, text and Excalidraw files Medium · estimate

Sticky notes and free text as styled floating roots. Lasso to “Make this a map”, loosen a branch into notes, drag a note onto a node, tidy a selection, a resizable ink pad. Import, export and paste of .excalidraw (route C).

Decisions only you can make

  1. Embed or build? Route A1 against route D. This page recommends D. If you want Excalidraw itself on screen soon, A2 is the contained way to try it.
  2. Are sticky notes nodes or elements? Phase 1 makes them floating roots, which is quick and gives conversion to maps for free, but means a note is always a potential tree. Making them elements later would need a migration.
  3. What shape is a stored element? Excalidraw’s own fields (top-left position, width, height, angle, seed, roughness, fill style) with Radiant extras kept separately, so files copy across unchanged; or a Radiant-native shape with a converter. The first is cheaper to interoperate; the second follows Radiant’s centre-and-size convention.
  4. How do free objects stack against maps? One band above the maps is simplest. Allowing objects behind and between maps is more expressive but adds draw calls, because the single branch mesh can no longer be drawn in one pass.
  5. Letters as tool keys, or an explicit Draw mode? The proposal is letters when nothing is focused. A mode is safer for people who type fast but adds a state to learn.
  6. ⌘G. Keep it for Generate Map, or give it to Group as every drawing tool does.
  7. File format v4. Elements only in doc.json, or also as indexed rows like nodes. And whether older Radiant builds should open a v4 file read-only or refuse it.
  8. Who owns presentation stops? If frames arrive, a stop can be a node, a frame or a bookmark. The presentation design should decide the list type before frames are built.
  9. A hand-drawn typeface. The mockups use a system font. Shipping one (Excalidraw bundles several) means checking its licence and adding it to the label atlas.
  10. Is a React dependency acceptable anywhere, even lazily loaded for an A2 spike? If not, routes A1 and A2 are closed and the question is settled.
  11. The sketch look: free objects only, or a theme for whole maps too? The second (idea 29) is what makes maps and drawings read as one picture.

  • Nothing was built or run. No embed, spike or benchmark exists behind any claim here. In particular, the cost of Excalidraw’s Canvas 2D layer repainting over WebGL2 inside Tauri’s WKWebView, and of an element mesh with thousands of shapes, was reasoned about, not measured.
  • rough.js in a Worker. I read its generator source and believe it needs no DOM, which would let it live in core/. I did not run it there.
  • Released against master. The sticky note element, and the lasso, autoshape and bucket-fill tools, appear in Excalidraw’s master branch. I did not confirm which of them are in the published 0.18.1 package.
  • Bundle size inside Radiant. The figures are Bundlephobia’s and jsDelivr’s for the published package, not a measurement of a Vite build of Radiant with it included.
  • Font licences. I did not check the licences of the fonts Excalidraw bundles, nor whether svg2pdf.js handles Excalidraw’s SVG output.
  • Excalidraw’s collaboration model. Taken from the hosted app’s dependencies and a 2020 blog post, not from reading its sync code. The text-to-diagram dialog exists in the open-source tree; I did not read what backend it expects.
  • Mermaid diagram coverage is quoted from the package README; the documentation page listing supported diagrams did not load.
  • Other tools. The FigJam, Miro, Heptabase, Obsidian, Freeform and Whimsical rows rest mostly on search summaries of vendor and community pages. I did not use the products, and the Miro point comes from community threads rather than an official statement.
  • tldraw pricing. The licence text was read in full; prices are quote-based and not published.
  • Stylus input. Whether WKWebView reports Apple Pencil pressure through Sidecar was not tested.
  • Radiant at extreme coordinates. The renderer’s high and low offset split suggests it is designed for distant content. I did not test how far.
  • Sizes. Every small, medium and large label is an estimate from reading the code, not from a breakdown of tasks.
