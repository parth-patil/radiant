# Functional requirements audit

This audit covers every requirement defined in the [functional features report](../../report/src/pages/features.html). The source baseline is `3d6d56e` (18 November 2026). Runtime evidence comes from the [integration handoff](../HANDOFF.md) and the recorded checks referenced in individual rows. The navigation and layout rows also include follow-up fixture results from the implementation in 5e14e17, bd41940, 0a2b376, f112f52 and 680625e. File names without a directory refer to modules in `src/lib/ui/`. Core, renderer, tooling and native paths are identified separately. The original audit used existing runtime evidence. The navigation and layout follow-up used isolated Chromium and native WebView fixtures.

The 142 entries include 134 verified, 0 implemented but unverified and 8 partial.

- **Verified** means existing evidence exercised the main acceptance workflow in the stated configuration. The last column records any narrower conditions or untested variants.
- **Implemented but unverified** means the expected implementation is present and direct acceptance evidence is absent or indirect.
- **Partial** means a capability or acceptance condition is incomplete or an important part needs separate acceptance evidence.
- **Missing** means the requested capability was not found in the audited source. Blueprint priorities, including Later, are preserved.
