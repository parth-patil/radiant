Product vision and scope

Radiant is a fast, local, organic-looking mind-mapping app for the Mac. An AI drafts the map from a topic and a requested style, the user reworks it, and any branch can be turned into pictures or SVG artwork. It is designed so that the user ends up remembering the content, which is why it also includes recall and review tools, and why the AI produces a draft to be improved and never a finished product to be admired. This page states what the app is for, who it serves, what it will and will not do in version 1, and the principles that settle design arguments.

Decision

Every requirement on the features page, the AI engine page, the art subtrees page, the engine page and the quality page should trace back to a statement on this page. If a requirement cannot be traced to a problem, a user, a differentiator or a principle below, it should be removed or this page should be corrected.

The problem

Mind-mapping tools solve drawing and organising well. They leave five problems open, each backed by the research pages.

  • Maps look alike. Most tools draw boxes and straight or lightly curved lines. The one-click hand-drawn style in Xmind is a filter on those shapes, and it does not give the tapered organic branches that Tony Buzan describes (desktop tools, Buzan). Memory-sport and sketchnote communities say hand-drawn maps are the more memorable ones, although no controlled study supports that (community, evidence).
  • AI maps are finished products that nobody learns from. Tools that turn a prompt into a map hand over a complete result, and reviewers say such maps include everything and are static. The evidence says that building or reworking a map helps memory more than studying a finished one (creating g = 0.72 against studying g = 0.43 in one meta-analysis). An AI that does all the work removes the useful part (evidence, community).
  • Large maps are slow and layouts are unstable. Users repeatedly complain that automatic layout moves nodes they have already placed, and the ranked needs on the community page put stable layout first. Reports of sluggish large files exist for MindManager, for Xmind (old reports, 2020 to 2021) and for Miro boards (search snippets). MindNode's own large-map speed is unmeasured (community, MindNode).
  • Layouts and structure are rigid. Tools are strict trees, or free-form canvases with no structure. Users ask for labelled cross-links, one node in several places, and linked sub-maps so that big subjects can be split (community).
  • Lock-in. MindNode keeps its documents inside iCloud as invisible files, and users complain about it. Many users want plain-text storage and vector export (MindNode, community).
Not verified

The AI tools page found no verified product that combines all of the following: AI tree generation from a topic and a natural-language style for the whole map, a per-subtree switch to generated raster or SVG art, and an engine that keeps every node as editable text. Xmind Make Image comes closest, per topic, and the search for subtree-level art found nothing. The claim rests on a limited search, so it is a gap that Radiant aims at and not a proven market.

Who it is for

The primary user is the developer who is building it. Radiant is first a personal tool, and the report treats the developer as a real user whose habits settle design questions. Three further profiles are plausible if the app is later shared. They are sketches to test requirements against, not market research.

The developer (primary)

Knowledge worker and learner, Mac, uses MindNode today

Maps a new technical topic, a paper or a domain before starting work, and wants to remember it afterwards. Works on the keyboard. Already has a ChatGPT subscription, so the Codex CLI is available. Wants the map to look distinctive and wants to open it again in a year.

The student or self-learner

Secondary

Prepares for an exam or a certification with a target date. Needs the AI draft, then recall and spaced review on that date. Will use the recall tools more than anything else, and may care more about the review schedule than about the art.

The visual note-taker

Secondary

Sketchnote or memory-sport hobbyist who currently draws maps by hand. Wants organic branches, pictures and a hand-drawn feel, and will judge the app mainly on how the maps look. Accepts a slower, more manual workflow.

The coding-agent user

Secondary, after version 1

Keeps design notes and project knowledge in maps and wants a coding agent to read them. Needs a documented file and an agent interface that is read-only by default.

What it does

The core loop has five steps. The first three are the main use of the app and the last two are what separates it from a drawing tool.

  1. Topic and style in. The user types a topic and picks or describes a style, such as a Buzan preset or a theme taken from an earlier map.
  2. A streamed draft. The AI, through the user's Codex login, writes the map line by line and nodes grow on the canvas as they arrive. The layout is always computed by the app and never by the model.
  3. Rework. The user edits, prunes, reorders and relabels with the keyboard, expands single nodes with the AI where needed, and decides what stays.
  4. Illustrate chosen branches. The user selects a branch and switches it to a picture or SVG representation. It stays connected to its parent, can still be folded, and keeps its text.
  5. Recall and review. The user hides branches or labels and recalls them, and the app schedules later reviews. The map is kept as a file the user owns.

Measured on your Mac with Codex CLI 0.167.0, the app-server mode starts streaming 2.8 to 3.7 seconds after a request, and a plain line-per-node format delivers about one complete node every 290 ms. These are single samples. See the Codex page and the AI engine page for the detail. The mode that shows nodes growing is built on that rate.

Design principles

These principles settle arguments. When two requirements pull in different directions, the one that follows the earlier relevant principle wins unless the report records a reason.

The tree is the truth, and looks are views
The document is a tree of text nodes, and vector, picture and SVG are three representations of the same subtree. Every node keeps its text, so search, outline, export and accessibility always work and a branch can return to plain form. See art subtrees and engine.
The AI drafts and the user decides
Generated output arrives as an editable draft, and the app pushes the user to rework and recall it. People learn from the effortful step. See evidence and practice.
Speed is a feature with a budget
Every performance claim is a number in the quality requirements and is checked, not hoped for. Where the budget and a visual effect conflict, the effect is simplified. See quality and stack.
Beauty must carry meaning
Pictures depict the concept, a few key nodes get the richest treatment, and decoration can be switched off. The evidence supports meaningful pictures and contrast and gives no support to ornament. See evidence.
Layout never surprises
The app does not move what the user has already seen unless asked, and changes animate. This is the most repeated complaint about existing tools. See community.
Keyboard first
Everything frequent is possible without the mouse, using the conventions most tools share, with the rest configurable. See desktop tools.
Files are yours
One visible file per map, open formats in and out, and generated assets that record how they were made. See MindNode and community.
Buzan's laws are defaults, not dogma
A preset applies his laws, each one a switch. Where the evidence disagrees with him, as it does on one word per branch, the rule is a default the user can change. See Buzan and evidence.
Honest about what the AI did
Document history marks AI and agent changes, generated assets record their prompt and model, and the app makes no percentage claims about memory gains. See MindNode and evidence.

Non-goals

  • Real-time collaboration and a hosted service.
  • A mobile app. The architecture keeps the option open but nothing is built for it.
  • A general whiteboard or diagramming tool. Radiant draws mind maps and linked maps, not flowcharts or free sketches.
  • A note-taking system. Nodes have notes, but long prose belongs in an outliner, and the app does not compete with them (community).
  • App Store distribution in version 1.
  • Generating a whole map as a single flat image. Maps are always built from nodes so that they stay editable, searchable and foldable (decision D-09).
  • Claims that mind maps or AI pictures raise memory by a stated percentage. The evidence does not support one.

Assumptions and open decisions

The user gave four answers that fix the starting point. The reference app is MindNode. The platform is macOS first, with a stack that can reach Windows and Linux later without a rewrite. The audience is a personal tool now and possibly shared or sold later, each user with their own Codex login. When stack options trade off, the best app by the fastest path wins, and performance must still be excellent. The working name Radiant is a placeholder.

The following decisions are still the user's to make.

  • App Store distribution. It would rule out the private WebKit flag that gives 120 fps (decision D-02). Shipping there would mean accepting 60 fps or building another way. The report recommends direct distribution.
  • Manual editing against AI generation. The report assumes the user reworks a draft heavily. If most use turns out to be generation with light editing, the recall and rework prompts matter more and detailed editing less.
  • Default style. The report proposes a restrained default and an optional Buzan preset. Whether the Buzan strict preset should be the default is open; the evidence page treats one word per branch as folklore and the app lets it be switched off.
  • Keyboard default. Shift+Return is the cross-tool key for a sibling before, while MindNode uses it for a new main node. The report binds both sibling-before keys and offers a MindNode preset.
  • File format. The brief proposes one SQLite file. Readable plain text answers lock-in better, so the format is to be revisited at the end of the first milestone.
  • Naming. The words "Mind Map" may be a trademark. The history page could not check registries, so the app should say "mind mapping" in its name and copy until that is done.
  • Pricing. If the app is sold, a one-time price or a charge tied to AI use fits the review complaints better than a subscription. The Codex login has its own terms to check.
  • Local-model AI. Some users want AI without cloud upload. The provider interface allows it later and nothing is promised.
  • Linux. Whether to accept a weaker WebView there or ship an Electron build.
