Roadmap, risks and open decisions

The plan is eight milestones. The first is a set of short experiments that settle the remaining unknowns before product code is written. The next two produce a usable app that turns a topic into an editable map. The signature features, picture and SVG subtrees, come after the canvas and the AI pipeline are solid, because they depend on both.

How to read the sizes

The durations are the report's own estimates for one developer working with coding agents, counted in focused weeks. Nothing in the research measures them. The only outside reference is the Zig researcher's estimate of two to four months to a first usable version for a WebView design, which milestones 0 to 2 are meant to match. Treat the order and the exit checks as the plan, and the durations as a guess to be corrected after milestone 0.

Milestone 0: the spikes

A spike is a throwaway experiment that answers one question. Each of these is a day or two of work. The first two reuse the test page already in your project at spikes/webview-120hz/.

Evidence

Three of these already have a first data point from this research: one picture took about 12 seconds and another about 29, one transparent-background request returned a transparent image, and one five-node SVG passed every contract check. Each was a single sample. The spikes turn single samples into rates.

What each milestone contains

M1 Canvas core

The foundation everything else stands on

  • Document model with stable node identifiers and an operation log for undo.
  • Tidy-tree layout for nodes of different sizes, two-sided and one-sided variants, running off the main thread.
  • WebGL2 renderer: one branch mesh, glyph quads, picture quads, culling.
  • Pan, zoom towards the cursor, zoom to fit, selection.
  • The standard keyboard model: Tab for a child, Return for a sibling, inline editing in a real text field.
  • Save, load, autosave and crash recovery in the SQLite document file.
  • The performance test rig and regression gate from the quality page.

M2 AI generation

The first thing you asked for

  • Host-side Codex client with supervision, isolation and cancel.
  • Topic and style prompt bar; nodes streaming onto the canvas.
  • Style request turned into a style sheet; a few presets.
  • Expand a node, regenerate a branch, shorten to keywords.
  • Every AI change is one undoable step, with what changed made visible.
  • Usage and rate-limit display.

M3 Organic style and outline

Where it starts to look like nothing else

  • Tapered, curved branches with a stored random seed; text on or beside the branch.
  • Themes, one colour per main branch, the Buzan preset and optional hints from his laws.
  • Radial and top-down layouts per main branch; manual moves as offsets.
  • Synchronised outline panel.
  • Markdown, OPML, FreeMind and JSON Canvas import and export; PNG, SVG and PDF export.

M4 Picture subtrees

The first half of the signature feature

  • Representation switch on any subtree, reversible.
  • Subtree style sheet and a reference image generated first.
  • Per-node image briefs, batch generation with placeholders and progress.
  • Transparent cut-outs, attachment points, branches ending under the picture.
  • Collapse, expand, regenerate one node, stale-art marking.
  • Asset cache with prompt and model recorded for each picture.

M5 SVG subtrees

The second half

  • Layout first, then a request for SVG that fills the computed boxes.
  • The node-group contract, validation, sanitising and the repair loop.
  • Rasterising visible SVG to textures by zoom level; live SVG when inspected closely.
  • Collapse by hiding groups; engine-drawn labels and branches.
  • Export of mixed maps to one SVG or PDF.

M6 Recall and review

What makes the maps stick

  • Collapse-and-recall mode and hidden labels on picture nodes.
  • Rebuild-from-memory exercise compared against the saved map.
  • Spaced review schedule with presets, including Buzan's.
  • AI-generated questions from a map, and a skeleton with blanks to fill.

M7 Packaging and polish

From project to product

  • Signing, notarisation and automatic updates.
  • Command-line tool and read-only agent server for maps.
  • Accessibility pass through the outline; reduced-motion and contrast checks.
  • Decision and first build for a second platform, if wanted.

A first week

  1. Day 1. Create the Tauri project. Run spike S1 with the existing test page. Record frame intervals with the flag on and off.
  2. Day 2. Run the same page in Electron (S2). Decide the shell for now.
  3. Day 3. Write the Rust Codex client: handshake, one streamed turn, interrupt (S5).
  4. Day 4. Stream node lines into a bare canvas: a topic becomes dots and lines.
  5. Day 5. Picture batch and SVG runs (S6, S7). Write up the numbers and fix the budgets.

At the end of that week every assumption this report could not test will have a number against it, and the first real milestone starts from facts.
